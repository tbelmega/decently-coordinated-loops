# {{REPO_NAME}} — work-stream data

The private data pool for the decently-coordinated-loops (DCL) workflow: one board
of parallel dev work-streams, maintained by agents, steered by {{OWNER}}. This repo holds only data and local policy — the workflow contracts,
tools, and skills live in the DCL clone at `{{DCL_HOME}}`.

## Files

| File / dir | What it is |
| --- | --- |
| `BOARD.md` | Flat index: one row per active work-stream. Regenerated by `bun run sync` — never hand-resolve its git conflicts, re-run sync instead. |
| `items/` | One file per work-stream — the source of truth. |
| `for-delivery/` | Verified work that left the active board but isn't released yet. Nothing lands here from a `no-deploy` project's ordinary path (its `tested` items are archived), but a `delivered` state the owner sets by hand still routes here from any project. |
| `archive/` + `ARCHIVE.md` | Finished work-streams: accepted / dropped, plus `tested` for a project whose `lifecycle` is `no-deploy`. |
| `INBOX.md` | {{OWNER}}'s dump zone: raw thoughts in, board items out. |
| `OUTBOX.md` | The mirror: everything agents need from {{OWNER}}, answerable in one line each. |
| `PROJECTS.md` | Per-project registry: repo paths (which drive the participation gate), gates, tracker locations. |
| `HOUSE-RULES.md` | Cross-project local policy the DCL skills defer to. |
| `loops.json` | Machine-read config: priorities, integration branch, per-project lifecycle tail, landed and review adapters, tokens. |

## Commands (run from this directory)

- `bun run check` — report-only board integrity check.
- `bun run sync` — regenerate `BOARD.md` and move item files per their state.
- `bun run landed` — check which items' work has landed on the integration branch.
- `bun run ready` — the dependency gate: which items' `depends-on` targets are satisfied.
- `bun run restamp` — advance `.loops-version` after reviewing a DCL upgrade.
- `bun run setup` — wire this machine to this repo: refresh the harness config block and
  set the review adapter. Safe to re-run; run it on every machine that joins.

## Local code review

If `loops.json → review.reviewer` is set (`bun run setup` offers this), an independent
reviewer model reviews a finished branch read-only, with no forge/PR. Drive it from the
target repo per the loops-review skill:

```bash
bun "{{DCL_HOME}}/tools/review/cli-review.ts" start --base <branch> --data-repo <this repo>
```

Once configured, agents run the review automatically at the final handoff of a tracked
item. Set the optional positive integer `review.maxRounds` to override DCL's default
cap of 3. Each logical round defaults to validated `diff`, `integration`, and
`adversarial` passes; `review.auditPasses` may select a non-empty subset. Optional
`review.metadataPaths` exact paths or `directory/**` patterns identify landing-only
bookkeeping that may be committed after a clean review. Optional `review.classes` waive
findings on record-keeping surfaces, and `review.confirmation: "scoped"` narrows a
qualifying confirmation round to the fix delta; both are described in the `loops-review`
skill. Any of these keys can be overridden per project under `projects.<name>.review`.
The current-HEAD gate is:

```bash
bun "{{DCL_HOME}}/tools/review/cli-review.ts" status --data-repo <this repo>
```

Contracts and protocols: the `loops-board`, `loops-queues`, `loops-pickup`,
`loops-dispatch`, `loops-review`, and `loops-setup` skills — installed into your
harness's skills tree,
or readable at `{{DCL_HOME}}/skills/`.
